## Reporting a vulnerability

We take security seriously. If you discover a vulnerability in any
Wrench-Studio project, please report it **privately** so we can address it
before public disclosure.

### How to report

Please use **one** of the following channels:

1. **GitHub Security Advisories (preferred)**
   Open a private security advisory on the affected repository:
   `https://github.com/Wrench-Studio/<repo>/security/advisories/new`

2. **Email**
   Send details to: `your-email@example.com` *(TODO: please update)*
   - Use a descriptive subject line, e.g. `[SECURITY] <repo>: short description`.
   - If the report is sensitive, request a PGP key in your first message
     and we will reply with one for encrypted follow-up.

### What to include

To help us triage quickly, please include:

- The affected **repository** and **version / commit SHA**
- A **description** of the vulnerability and its impact
- **Steps to reproduce** or a proof-of-concept
- Any **known workarounds** (if applicable)
- Your name / handle if you'd like **credit** in the advisory

### What to expect

| Step | When |
| --- | --- |
| Initial acknowledgement | within **3 business days** |
| Triage & impact assessment | within **7 business days** |
| Patch & coordinated disclosure | depends on severity & fix complexity |

We will keep you informed of progress and credit reporters who request it
in the published advisory.

## Disclosure policy

- Please **do not** open a public issue, pull request, or social-media
  post about the vulnerability before a fix is available.
- We follow a **coordinated disclosure** model: we aim to publish a fix
  and advisory together, and we are happy to align timing with the
  reporter.

## Recognition

We appreciate the security community's help in keeping Wrench-Studio
projects safe for everyone. Reporters who follow this process and request
credit will be listed in the relevant GitHub Security Advisory.
